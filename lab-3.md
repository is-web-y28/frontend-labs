# Лабораторная работа 3. Интерактивное взаимодействие средствами JavaScript

Продолжение первых двух лабораторных: тот же сайт и репозиторий. Задача — освоить события, DOM, ES Modules и сохранение данных на чистом JavaScript.

## Формы, списки и фильтрация

Добавьте на одну из страниц раздел с формой, списком и поиском или фильтрацией: отзывы, список покупок, план поездки или другой вариант по теме сайта. Если раздела нет в макете, добавьте его в общей стилистике. Отдельное приложение делать не нужно.

Требования к функциональности:

- форма содержит подписанное текстовое поле, ещё хотя бы одно осмысленное поле (категорию, дату, оценку и т. п.) и кнопку отправки;
- данные проверяются средствами HTML и JS: некорректный ввод, включая текст из пробелов, не создаёт элемент и сопровождается объяснением ошибки; после успешного добавления форма очищается;
- любой элемент можно удалить кнопкой; добавление, удаление и поиск или фильтрация работают без перезагрузки;
- поиск по тексту или фильтрация по полю не изменяют исходный список; сброс возвращает все оставшиеся элементы. Добавление и удаление корректно работают при активном фильтре: неподходящий новый элемент не виден до сброса, удаляется именно выбранный элемент;
- пустой исходный список и отсутствие совпадений сопровождаются разными сообщениями;
- исходный список автоматически сохраняется в `localStorage` после изменений и восстанавливается при открытии страницы, в том числе после удаления всех элементов. Используйте `JSON.stringify` и `JSON.parse`; при отсутствии данных список пуст;
- некорректный JSON или структура данных, ошибки чтения и сохранения не ломают раздел: он продолжает работать и сообщает о проблеме.

Сохранение фильтра, редактирование элементов и дополнительный интерактивный компонент не требуются.

Требования к реализации:

- JS вынесен в ES Modules с `import` и `export`; точка входа подключена через `<script type="module">`;
- разделены данные и хранилище, отображение и обработчики. Модуль данных не обращается к DOM; исходный список — массив объектов, отображаемый вычисляется с учётом фильтра;
- элементы имеют устойчивые уникальные идентификаторы, сохраняемые вместе с данными; индекс массива идентификатором не является;
- события обрабатываются через `addEventListener`, обновление списка не накапливает обработчики; используйте `const`, `let` и функции, не размещайте состояние в `window`;
- пользовательский текст выводится через `textContent` или аналогичный безопасный способ, не как HTML;
- действия выполняются кнопками, переходы — ссылками; весь раздел доступен с клавиатуры, оформление задаётся в CSS и сохраняет адаптивность и видимый фокус;
- пользовательские сценарии не вызывают необработанных ошибок в консоли.

## Слайдеры

На страницах сайта есть слайдеры: элементы (картинки, карточки и т. п.) переключаются кнопками «назад» и «вперёд» или точками-индикаторами. Оживите все слайдеры из макетов. Новые слайдеры добавлять не нужно.

Требования к функциональности:

- кнопки «назад» и «вперёд» и точки-индикаторы переключают слайды без перезагрузки страницы; в каждый момент виден только текущий слайд (или группа слайдов, если так задано в макете);
индикатор текущего слайда выделен и обновляется при любом способе переключения;
- поведение на границах одинаково для всех слайдеров: либо переключение зацикливается, либо крайняя кнопка блокируется атрибутом disabled; выход за границы списка слайдов не вызывает ошибок;
- несколько слайдеров на странице работают независимо: переключение одного не влияет на другие;

Автоматическая прокрутка и свайпы не требуются.

Требования к реализации:

- логика слайдера вынесена в отдельный ES Module; одна функция инициализации подключается ко всем слайдерам сайта и принимает корневой элемент слайдера;
- состояние каждого слайдера (номер текущего слайда) хранится внутри функции инициализации, а не в window и не в общих переменных модуля; обработчики назначаются через addEventListener один раз при инициализации;
- смена слайда выполняется переключением классов или атрибутов; внешний вид слайда и анимация переключения задаются в CSS и сохраняют адаптивность.

## Общее требования

Нельзя: JS-библиотеки и фреймворки, TypeScript, обработчики в HTML (`onclick`, `onsubmit` и аналогичные). API, серверная часть и сборщик не нужны.

> [!NOTE]
> Запускайте сайт через локальный HTTP-сервер (Live Server или `python3 -m http.server 8000` из корня проекта) либо опубликуйте его. `file://` не подходит для проверки ES Modules.
